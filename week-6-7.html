Task 1/Event handlingHint

Hand React the function. Do not call it.

function handleClick() {
  console.log("clicked");
}

<button type="button" onClick={handleClick}>Click me</button>
Correct
onClick={handleClick}
Runs immediately, then never again
onClick={handleClick()}

The second one calls the function while React is building the page, and hands React whatever it returned. Note the capital C: onClick, not onclick.

src/components/ProfessionalCard.jsx
function ProfessionalCard({ professional }) {
  function handleContact() {
    console.log(`Contacting ${professional.name}`);
  }

  return (
    ...
    <button type="button" className="btn" onClick={handleContact}>
      Contact
    </button>
    ...
  );
}

handleContact lives inside the component, so professional is already in scope — you don't pass it in.

WorksThree cards, three different names in the console

Two mistakes to check for: calling instead of passing (onClick={handleContact()}), and trying to pass professional into the handler when it is already in scope.

src/components/ProfessionalCard.jsx · temporary

Add a click counter to the card. Then delete it.

  • First, do it wrong on purpose. Write let count = 0; inside the component and a button that does count = count + 1; and logs it.The console counts up. The page never changes. Understand why before moving on.
  • Then fix it with useState. The number on the button should go up when you click it.

Break it firstA plain variable changes, and nothing re-renders
Task 2/useStateHint

State is a variable React watches.

import { useState } from "react";

const [count, setCount] = useState(0);
  • count — the current value
  • setCount — the only way to change it
  • useState(0) — the starting value, used on the first render only

Changing a plain variable is invisible to React. Calling the setter tells React "this changed — draw the page again." The names in the brackets are yours to choose; the order is not.

Task 2/useStateSolution
src/components/ProfessionalCard.jsx — temporary
import { useState } from "react";

function ProfessionalCard({ professional }) {
  const [count, setCount] = useState(0);

  return (
    ...
    <button type="button" className="btn" onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
    ...
  );
}

Each card keeps its own count. One line of code, three independent counters — because state belongs to the card on screen, not to the function you wrote.

Now delete itThe counter has done its job

The arrow wrapper is needed here for the same reason as Task 1 — setCount(count + 1) is a call, so it has to be wrapped in a function React can call later.

Task 3/Conditional renderingHint

A ternary picks between two things.

condition ? whenTrue : whenFalse

Use it for the label, and use it in the JSX to choose between the element and null. null means "render nothing here."

<p>{isOpen ? "Open" : "Closed"}</p>

{isOpen ? <p>Some details</p> : null}

The description is a <p className="professional-description"> — keep that class, it's what draws the line above the text.

Task 4/Lifting state upTask

src/App.jsx and src/components/ProfessionalCard.jsx

Make the Delete button remove the card.

  • Put the list of professionals into state — in App, not in the card.A card cannot delete itself out of a list it doesn't own. The list has to live in the closest shared parent.
  • Pass a delete function down to each card as a prop.
  • Deleting a card must not disturb the others — if another card is showing its info, it stays open.
Task 4/Lifting state upHint

Never change the array. Build a new one.

const [items, setItems] = useState(SEED_ITEMS);

function handleRemove(id) {
  setItems((prev) => prev.filter((item) => item.id !== id));
}
  • .filter() returns a new array with the matches kept — the original is untouched. .splice() edits in place; React will not notice it.
  • (prev) => means "whatever the list is right now, here is the replacement".
  • Down in the card: onClick={() => onDelete(professional.id)}

Why key={professional.id}

The key is how React tells the cards apart. Open the third card's info, then delete the first. With an id as the key, the right card stays open. With the array position, the wrong one does.

Task 5/Derived stateHint

Two pieces of state would drift apart.

You have the full list and you have what was typed. The visible list is just those two put together — a plain const, recalculated on every render, so it can never be stale.

const [query, setQuery] = useState("");

const visible = professionals.filter((p) =>
  p.name.toLowerCase().includes(query.toLowerCase()),
);
  • A controlled input needs both: value={query} and onChange={(e) => setQuery(e.target.value)}
  • An empty search matches everything — "".includes("") is true.

Task 6/Controlled formTask

src/components/ProfessionalForm.jsx and src/App.jsx

Make the form add a new professional.

  • All four fields controlled by React, held in one object of state.
  • One change handler for all four — not four handlers.
  • Submitting adds a card to the list and clears the form.
  • The page must not reload when you submit.
Task 6/Controlled formHint

The input's name becomes the key.

function handleChange(e) {
  setForm((prev) => ({ ...prev, [e.target.name]: e.target.value }));
}
  • ...prev copies every field you're not touching.
  • [e.target.name] in square brackets means "work out this value, then use it as the key". The inputs already have name="name", name="title" and so on.
  • e.preventDefault() on submit, or the browser reloads the page and every piece of state is gone.
  • The form does not own the list. It hands the values up: onSubmit(form).
Task 6/Controlled formSolution 1/3
src/components/ProfessionalForm.jsx — the logic
import { useState } from "react";

const EMPTY_FORM = { name: "", title: "", email: "", description: "" };

function ProfessionalForm({ onSubmit }) {
  const [form, setForm] = useState(EMPTY_FORM);

  function handleChange(e) {
    setForm((prev) => ({ ...prev, [e.target.name]: e.target.value }));
  }

  function handleSubmit(e) {
    e.preventDefault();
    onSubmit(form);
    setForm(EMPTY_FORM);
  }
Task 6/Controlled formSolution 2/3
src/components/ProfessionalForm.jsx — edit the inputs already in the file

  />
  ...
</form>

Every field gets the same two lines — value and onChange — with only form.name changing to form.title, form.email, form.description. The <textarea> works exactly the same way.

Task 7/ValidationTask

src/components/ProfessionalForm.jsx

Refuse to add a professional when the form is wrong.

  • Name — cannot be empty
  • Title — at least 3 characters
  • Email — must look like an email address
  • Description — at least 20 characters

Show the message under the field it belongs to, using <span className="form-error">. Check on submit — not while they are still typing.

Task 7/ValidationHint

Validation is not a React problem.

It's a function that takes an object and returns an object. No hooks, no JSX — so write it outside the component. An empty result means "all good".

function validate(form) {
  const errors = {};

  if (form.name.trim() === "") {
    errors.name = "Name is required";
  }

  return errors;
}
  • Keep the messages in a second piece of state: const [errors, setErrors] = useState({});
  • Object.keys(errors).length tells you how many problems there are.
Task 7/ValidationSolution 1/2
src/components/ProfessionalForm.jsx — above the component
const EMAIL_PATTERN = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

function validate(form) {
  const errors = {};
  if (form.name.trim() === "") {
    errors.name = "Name is required";
  }
  if (form.title.trim().length < 3) {
    errors.title = "Title must be at least 3 characters";
  }
  if (!EMAIL_PATTERN.test(form.email.trim())) {
    errors.email = "Enter a valid email address";
  }
  if (form.description.trim().length < 20) {
    errors.description = "Please write at least 20 characters";
  }
  return errors;
}
Task 7/ValidationSolution 2/2
src/components/ProfessionalForm.jsx — inside the component
const [errors, setErrors] = useState({});

function handleSubmit(e) {
  e.preventDefault();

  const nextErrors = validate(form);
  setErrors(nextErrors);

  if (Object.keys(nextErrors).length > 0) {
    return;
  }

  onSubmit(form);
  setForm(EMPTY_FORM);
  setErrors({});
}

<input id="name" name="name" className="form-input"
  value={form.name} onChange={handleChange} />
{errors.name ? <span className="form-error">{errors.name}</span> : null}
WorksSubmit empty — four messages, no new card

The order inside handleSubmit matters: validate, store the messages, then stop. Calling onSubmit before the check is the usual bug.

.trim() is what stops a form full of spaces from passing.

Task 8/EditingHint

Store the id. Let the key do the rest.

App remembers which professional is being edited — one id, not a copy of their details. Move EMPTY_FORM up to App and pass the starting values down.

const [editingId, setEditingId] = useState(null);
const editing = professionals.find((p) => p.id === editingId);
The trick

Change a component's key and React throws the old one away and builds a fresh one — so the form re-reads its starting values by itself. Same idea as Task 4, used on purpose.

Updating one item in a list is .map(): return a changed copy for the one you want, and the original for everything else.

Task 8/EditingSolution 1/3
src/App.jsx — add or update
const EMPTY_FORM = { name: "", title: "", email: "", description: "" };

const [editingId, setEditingId] = useState(null);
const editing = professionals.find((p) => p.id === editingId);

function handleSubmit(values) {
  if (editingId) {
    setProfessionals((prev) =>
      prev.map((p) => (p.id === editingId ? { ...p, ...values } : p)),
    );
  } else {
    setProfessionals((prev) => [
      ...prev,
      { ...values, id: crypto.randomUUID() },
    ]);
  }
  setEditingId(null);
}

Task 9/Confirm deleteTask

Task 9/Confirm deleteHint + solution

window.confirm() stops the page and hands you back true or false. Deal with the "no" case first and leave early — it keeps the rest of the function flat.

src/App.jsx
function handleDelete(id) {
  const professional = professionals.find((p) => p.id === id);

  if (!window.confirm(`Delete ${professional.name}?`)) {
    return;
  }

  setProfessionals((prev) => prev.filter((p) => p.id !== id));

  if (editingId === id) {
    setEditingId(null);
  }
}
